# Decisions
- Name `perusal`, isolated in `crates/core/src/brand.rs` (spec).
- License MIT OR Apache-2.0; LICENSE-APACHE holds a pointer to the canonical text rather than the full text (fetch full text before release).
- GPUI not wired in M0: app crate is a stub so `cargo build --workspace` stays fast and green; the GPUI pin is chosen when M3 starts, per spec.
- Synthetic MR generator lives in `perusal-cli` (`perusal-cli gen <dir>`), using the git CLI.
- Line/word diff uses `similar` (inline feature) instead of imara-diff: stable API, built-in word-level inline changes.
- Tree-sitter highlighting ships rust and python grammars first; other languages load lazily in later work (return no spans now).
- Re-anchor of drafts across a head move uses a line-diff map; ranges where either end changed are flagged for manual placement.
- Token storage: FileStore (mode 0600, outside SQLite) is implemented; OS keychain backend (keyring crate needs libdbus) is deferred behind a future `keychain` feature. File is not encrypted; documented risk.
- GitLab viewed-state: the API exposes none, so marks stay local (`Unsupported`). GitLab "request changes" has no equivalent: submit returns `Unsupported` and the UI hides the control.
- GitHub viewed sync uses GraphQL markFileAsViewed/unmarkFileAsViewed (needs PR node id lookup first); implemented but only mock-tested.
- GitLab submit sends positions with null base/start SHA; real instances need the MR diff_refs filled in (to verify against a live host).
- GPUI (superseded by the next entry): crates.io `gpui` 0.2.2 was fetched but fails to compile in this sandbox (transitive `xattr` cannot find libc::ENOATTR on this toolchain/libc, also after `cargo update`). No window could be built or run, so `perusal-app` is a lib of tested view models (vm, tabs, keymap, theme) plus a stub binary. Wiring GPUI (pinned) is the first step on a machine where it builds; the view-model API is what the views bind to.
- Built-in theme colors are first-pass values validated by `perusal theme check` contrast rules, not hand-tuned.
- GPUI resolved: Zed's git GPUI pinned to rev 0855410ccd2040efbbf14d71409166b6c472e0bd (2026-09-01) builds and runs (latest Zed head needs an unstable rustc feature, `trim_prefix_suffix`, and crates.io 0.2.2 trips on `xattr`). Linux needs libxkbcommon-dev, libxkbcommon-x11-dev and libwayland-dev at link time. The GUI lives in `crates/ui` (bin `perusal`), a workspace member. `gpui_platform` is used with font-kit, wayland, x11.
- GUI v0 scope: local-branch review window (file list, virtualized diff with tree-sitter colours and word highlights, progress bar, filter bar, batch flow, commit graph with click-to-scope, draft comments, zoom). Not yet: tabs, side-by-side view, recent-reviews page, quit prompt, command palette, remote MR opening, submit dialog, thread display, AI chat, CI icon, theme/keymap file loading (keys are hard-coded).
- Home screen (`crates/ui/src/root.rs`): recent reviews (pin, delete, reopen by stored key), open local branch, open MR/PR by URL, browse open MRs of `host/owner/repo`, token prompt on 401/404. Remote open = host API for metadata + blobless bare clone cache under the data dir + fetch of the MR ref and base branch; the base is the merge-base. The access token reaches git only through host-scoped `GIT_CONFIG_*` environment variables (`http.https://host/.extraHeader`), never on disk. Default database moved from ./perusal.sqlite to `~/.local/share/perusal/perusal.sqlite` for the GUI (`perusal-cli` still defaults to the cwd; pass `--db` to share).
- Remote opening could not be run end to end here: api.github.com returns 403 in the sandbox, so only the error path was exercised (plus the lower layers: clone/fetch/merge-base tests, provider contract tests). Submitting reviews, threads and the AI chat are still not in the window.
- GUI redesign: GitHub-style layout (header bars, bordered cards, file tree with status badges, file cards with Viewed checkbox, hunk separators, commit timeline, drafts panel, kbd chips). Theme schema gained required `ui.surface`, `ui.muted`, `ui.hover`. Fonts: Inter (else the platform UI font) for UI, first installed of JetBrains Mono / Fira Code / Cascadia / SF Mono / DejaVu Sans Mono for code.
- Text input is a real component (`perusal_app::textfield`, unit-tested): caret, selection, word moves, Ctrl+C/X/V and Shift+Insert, via the GPUI clipboard. Mouse caret placement and drag selection are not implemented. Pasting a URL without a scheme gets https:// added.
- Bug fixed: `gitops::show` trimmed file content, dropping the final newline and mis-diffing every last line; it now returns exact content.
- Settings panel (`s`): theme (built-in and custom, follow-OS pair), group related files, Files panel mode, default diff view, markdown default, AI agent and custom command. Stored in `~/.config/perusal/settings.toml`. It is reachable from the review screen only; the Home screen has no settings entry yet.
- Diff: unified and split views (`diff::text::split_pairs`), per-file toggle plus a default. Markdown preview via pulldown-cmark rendered to GPUI elements (no images, no syntax colours in code blocks).
- Selection: click, drag or Shift+click rows; comments and AI use the new-side line range (removed-only selections fall back to old line numbers). Drafts have no side field, so a comment on a removed line is anchored by its old number.
- Manual file groups (Ctrl/Shift+click, Review together) are in-memory per session and not persisted.
- AI in the GUI: headless CLI per request (no ACP streaming yet), run in a `git archive` snapshot under the data dir, minimal environment (credential-like variables are dropped, so API-key-only setups need the agent's own login), 15 minute timeout. AI review output must be the JSON array in `skills/review.md`; anything else shows an error with the first 300 characters. Only tested against a fake agent script; the real agent CLIs were not available here.
- Icons: Material Icons (Apache 2.0), converted from the npm package's WOFF to TTF with fonttools and embedded (`crates/ui/assets`, notice and licence included). `icons.rs` holds codepoints extracted from the font's ligature table. Icon-only buttons carry tooltips.
- Split diff falls back to a single column for added and deleted files (one side is always empty). Single-column rows hide the empty line-number gutter.
- Mouse text selection in inputs maps x positions to characters by shaping the text with the field's font (`shape_line`), using a canvas probe for the field bounds. Password-style fields hit-test against the masked text.
- `ai` and `comments` filter fields are now fed from saved drafts (`ReviewVm::sync_review_state`); they previously never changed. `unresolved` stays 0 until threads are shown in the window.
- Symlinks are detected from git file modes (`git diff --raw -z`, mode 120000 on either side). The numstat/raw parsing now uses `-z`, which also fixes rename paths (`old => new`) that were previously wrong.
- Grouping is rule based (`diff::rules`): each rule is a regex with a `stem` group, keyed per rule so `foo.rs` and `foo.py` do not group. Replaces the single stem heuristic. The spec's "code-aware grouping through imports" is still post-v1.
- Agents: Claude Code is run with `--output-format stream-json --verbose --permission-mode plan` so tool activity can be shown live; other agents show elapsed time and streamed lines. Cancel kills the process. Effort maps to MAX_THINKING_TOKENS (Claude), `model_reasoning_effort` (Codex) and the `#variant` suffix on the model, `-m provider/model#variant` (opencode; there is no `--variant` flag on `opencode run`, which printed its usage text); Gemini has no effort control. These flag names are taken from each CLI's documentation as I know it and were not verified against the real CLIs here.
- Finish review posts through the provider (`submit`): inline comments for drafts with a file and line range, drafts without one are appended to the summary. After a successful post the drafts are deleted and the review marked submitted. Only tested against mocks (providers) and the dialog flow for local reviews; a real remote post was not run.
- Rendered-markdown comments anchor to the source line range of the clicked block(s) from pulldown-cmark offsets. Nested blocks (list items) are commented as part of their list.
- Cursor styles are set explicitly (pointer on clickable elements, text on inputs, col-resize on dividers). They could not be verified visually in the headless display.
- Public repositories: an empty token no longer sends `Authorization: Bearer `/`PRIVATE-TOKEN` (GitHub answered 401, which the app mistook for a private repository). Contract test added.
- Tabs live in `Root`; each review is an Entity<View> that emits `ViewEvent`s (Home, OpenSettings, Notice, Renamed, Ci). One toast queue (`perusal_app::notify`) replaces the old status line and banner; important notices also go to the desktop (`notify-send` on Linux, `osascript` on macOS; not implemented on Windows).
- Settings is one shared entity used by Home and every review; it also hosts first-run setup. Accounts: token paste, `gh auth token` / `glab auth status --show-token` import (glab output parsing is unverified against the real CLI), OAuth device flow (needs a per-host client ID; GitLab's device flow is not implemented, use a token or glab).
- Remote polling (state, head, CI, comments) every 60 s, 15 s while CI runs, per open remote review; local branches look for an MR on their origin every 90 s. A changed head is reported as "new commits": telling a force-push apart needs the new commit locally and is not done yet (the `events` module supports it).
- The diff uses GPUI's variable-height `list` so comment cards can sit inline; selection is by selectable-row ordinal so it survives comment rows being added or removed. Own posted remote comments cannot be edited yet; drafts (including AI ones) can.
- Syntax highlighting parses whole files and maps spans to lines (multi-line strings and comments work). Tree-sitter grammars: rust, python, javascript, typescript, tsx, json, go, c, cpp, java, bash, css, html. Other code extensions use a lexical fallback (comments, strings, numbers, common keywords); markdown and plain text are not highlighted.
- Multi-line text inputs (comment editor, finish summary) support Enter, Up/Down, Home/End, selection and Markdown helpers; there is no scrolling inside them beyond a fixed maximum height.
- Whitespace: `FileStat.meaningful` comes from a third `git diff -w --numstat` (files that vanish from it are whitespace-only; fields `whitespace`, `meaningful` in the filter language). The toolbar toggle hides those files and, inside files, uses `diff_lines_ws` (lines compared with all whitespace removed; context shows the new text; no word highlights).
- Sort is a tiered panel over the same expression text: `filter::parse_tiers/format_tiers` split on top-level commas and a trailing ` asc`/` desc`, so presets and the raw expression box stay compatible. Sorting is ignored in directory-tree order, so a warning is shown there.
- "Generate with AI" (filter, sort, grouping rule) runs the configured agent in an empty temp dir with a prompt built by `agents::gen_prompt` (the expression reference comes from `filter::reference()`, generated from the field/function tables so it cannot drift). The answer must be one JSON object; it is parsed, compiled/validated with the real parsers and only then applied (a rule is dropped into the form for review instead of being added blindly).
- GitLab inline comments: draft-note positions now carry the MR's real `diff_refs` (base/start/head SHA) plus old/new path and new line. With null SHAs GitLab files the note as a plain MR thread (the bug that was reported). Remote suggestion diffs are shown only for your own drafts (their original lines are known); others render as a plain suggestion block.
- Markdown rendering: inline spans are laid out as a wrapping row of word elements (not one styled text run) so code can use the mono font, links are clickable (`cx.open_url`) and bold/italic do not depend on text-run styling. Fenced code is syntax highlighted via the same tree-sitter pipeline as diffs.
- Window chrome: `window_decorations = Client` with our own tab-strip title bar (drag to move, double click to maximize, minimize/maximize/close buttons) and 5 px resize handles using `start_window_resize`; the setting is live (`request_decorations`). Unverified on real window managers (the test display has none).
- Desktop notifications have per-event switches (`events::DESKTOP_EVENTS`, `Settings.desktop_events`, missing = on) under a master switch. `gh`/`glab` import now discovers every logged-in host (`hosts_from_status`) so GitHub Enterprise and self-hosted GitLab are added with their tokens.
- Agent programs are found through `agents::find_program`: the process PATH, then the login shell's PATH (`$SHELL -ilc`, cached, warmed at startup), then usual user install dirs (~/.opencode/bin, ~/.bun/bin, nvm, Homebrew...). A GUI started from a launcher has a bare PATH, which made the onboarding check flip between found and not found. The same directories are passed to the agent process.
- Single-line and multi-line fields scroll horizontally: the part before the caret shrinks from its left edge, so the caret and your typing stay visible; mouse hit-testing applies the same scroll.
- Bold/italic: if the UI font has no real bold/italic face (GPUI silently falls back to regular), another installed family that has one is used for those spans (`kit::variant_families`).
- The diff list measures all rows up front (up to 4000) so the scrollbar range is exact; before, the thumb kept shrinking as unseen rows were measured, most visibly in grouped batches.
- Markdown in a batch: the rendered/source toggle shows when any file is markdown and the setting is respected per file (rendered files appear as a preview section; commenting on blocks still needs the file on its own). Top-level lists are split so each bullet is its own commentable block. Collapsed (generated/large) files have a "Show anyway" button; binary files explain why there is nothing to show.
- CI/CD: `.github/workflows/ci.yml` runs tests, clippy (`-D warnings`) and the extension tests on every pull request. `release.yml` runs on `v*` tags: the version is the tag without the `v` (v1.2.3 -> 1.2.3; a suffix like -rc.1 marks a pre-release), written into the workspace `Cargo.toml` inside the runner only (the repository is not changed), then builds deb, rpm, AppImage, Flatpak bundle, a tarball and the two browser extensions, adds SHA256SUMS and publishes a GitHub release. Built on ubuntu-22.04 for the oldest glibc. Deb/rpm versions turn `-` into `~` so pre-releases sort before the final release. None of this could be run here (no Actions runner, appimagetool, rpmbuild or flatpak-builder in the sandbox); only the deb script and YAML syntax were checked.
- TLS trust: reqwest uses `rustls-tls-native-roots`, so the system trust store (`SSL_CERT_FILE`/`SSL_CERT_DIR`, else /etc/ssl/certs etc.) is honoured and self-hosted GitLab/GitHub Enterprise with a company CA works without extra setup. The bundled webpki roots are no longer used; `PERUSAL_CA_FILE` still adds one extra CA on top. Reason: the old build only trusted public CAs plus `PERUSAL_CA_FILE`, unlike git, which already used the system store.
- GitLab "my reviews" links are rebuilt as https://<host>/<project>/-/merge_requests/<iid>: instances behind a TLS proxy report http:// web_urls, which the opener rejects.
- Collapsed comments are not rows: they become gutter icons on the line they belong to (file-level and outdated ones keep a one-line collapsed card). Hovering a card or icon highlights the lines of its range (threads only know their end line). Resolved threads are collapsed once when first seen (`auto_c`), so expanding one by hand sticks.
- Agent response timeout is `agent_timeout_mins` in settings (default 15 = the old 900 s; 0 = no limit). A running agent can always be stopped with Stop.
- Overview is a centre-pane page (tabs Overview | Changes, `O` toggles; `first_view` setting, default overview; remote reviews only) instead of a sidebar section; it shows MR title/state/branches/description and path-less threads. GitLab general notes are now listed (system notes skipped); GitHub issue comments are fetched best-effort. Replying to those general threads from the app is not built yet.
- Home search: one shared matcher (`perusal_app::search::matches`, all words must match any of the listed fields); the filter chips still apply on top. Search fields are not part of the Tab cycle of the open-a-review form.
- Release fix (v0.1.0 run failed in the Flatpak step with "No remote refs found similar to flathub"): the workflow added flathub system-wide while `build-flatpak.sh` installs with `--user`. Both now add the remote with `--user` (the script does it itself, so local builds work too). The rest of the packaging and the publish step were not reached by that run, so they are still unverified.
- Release fix 2 (second v0.1.0 run failed in flatpak-builder: "Failed to execute child process eu-strip"): the runner needs `elfutils` (eu-strip, eu-elfcompress); added to the apt list in release.yml. Local `build-flatpak.sh` needs it too. The Flatpak runtime org.freedesktop.Platform 24.08 is end-of-life (only a warning in the log); moving to a newer runtime is left for later.
- GitLab multi-line comments: the draft-note position now carries `line_range` (start/end line codes `sha1(path)_old_new`, type `new`) besides `new_line`; with `new_line` alone GitLab anchors the note to the last line only. Old-side numbers come from `perusal_diff::text::old_line_for_new` (an added line gets the next old line number, as GitLab's parser does). Single-line comments are unchanged.
- AI review prompt now includes the posted threads (author, text, resolved flag, capped) and the reviewer's local drafts (AI drafts tagged), so the agent does not repeat them. The MR overview (title/description) is deliberately not inlined: the prompt gives the MR URL and tells the agent to fetch it if needed. Local-branch reviews have no URL and no threads. Chat prompts are unchanged.
- Setting `publish_instantly` (default off, remote reviews only): a new comment is saved as a local draft first (never lost) and then posted via the normal submit path (one comment, verdict Comment); the draft is deleted only after the host accepts. Finish review button and the `f` key are hidden, so Approve/Request changes need the setting turned off. Existing/AI drafts get a "publish now" icon. Edits of existing drafts stay local.
- First-run setup: the accounts step now has the same "Import all logins" (gh + glab) card as Settings (shared `import_all_card`); the agent step has a Model dropdown (shared `model_control`, same list as Settings) and switching agent clears model/effort. The agent preselected at first run is the current one if installed, otherwise the first installed in `AGENTS` order (claude, gemini, codex, opencode); `pick_installed_agent` is unit tested. With none installed the default stays.
- Prompt templates (PR #10 review): all agent prompts (Ask AI, AI review, filter/sort/rule generation) are Markdown files with `{{field}}` placeholders. Defaults ship in `crates/agents/prompts/` and are written, with an `AGENTS.md` documenting the fields, to `~/.config/perusal/prompts/` on first use, never overwritten; a user file overrides the built-in, an empty one falls back. Fields are filled in one pass so untrusted text containing `{{...}}` is never expanded. Replaced `skills/review.md` (and its deb install line) by `prompts/review.md`.
- Diff horizontal scroll: long code lines scroll sideways with the trackpad/wheel x delta, one shared offset for all rows (code cells clip and shift; gutters stay put). The max offset comes from the widest rendered line (chars x 0.6 em, monospace estimate), and the offset resets when the shown batch changes. Review title: clicking the title text enters rename mode, same as the pencil button.
- Diff horizontal scrollbar: a draggable track floats just above the bottom bar when any rendered line overflows (click the track to jump, drag the thumb); the review title shows a hover highlight (background + accent border) to signal click-to-rename.
- Collapsed file-level and outdated comments now show as gutter icons (anchored to file header / last row) like line comments, instead of full-width cards.
- GitHub threads: resolved state now read via GraphQL reviewThreads (REST lacks it), so resolved threads start collapsed; failures are ignored.
- Submit: remote review comments on lines outside the diff are folded into the review summary (file:line prefix) instead of failing the whole review with GitHub 422 'Line could not be resolved'.
- GitHub resolved-thread lookup pages through GraphQL (cap 50 pages); collapsed-comment icons only anchor on rows that draw them, else the comment stays a card.
- Whole-MR (global) drafts stay local until submit and are then posted as their own threads, not folded into the review summary: GitHub posts them as issue comments right after the review (a review with nothing but general comments is skipped; if a later comment fails the review is already posted, so the error is shown and the remaining drafts are kept), GitLab as unpositioned draft notes inside the atomic bulk publish.
- User pictures: hosts report avatar URLs (author, assignees, reviewers, comment authors); they are remembered by login (case-insensitive, host-agnostic), downloaded once in the background into `<data>/avatars/` (https only; the token saved for that exact host is sent, for self-hosted GitLab) and drawn round. GitHub falls back to `https://<host>/<login>.png`. Anything without a picture (loading, failed download, local git committers, GitLab users without a reported URL) shows a generated placeholder: two initials on one of 12 hashed colours, foreground a lighter or darker shade of it, whichever contrasts better (`app::avatar`, unit tested). Commit authors map to an account via GitHub noreply emails or a known login equal to the name/email local part.
- My reviews search: qualifiers (`author:`, `assignee:`, `reviewer:`, `label:`, `project:`, `host:`, `state:`, `kind:`, `is:draft`, `user:`, leading `-` negates) plus free text that also searches the overview text; Person and Label chips are built from the loaded list and filtering is client-side over the 50 newest per role. GitHub's search results carry no requested reviewers, so `reviewer:` only matches on GitLab.
- Middle-clicking a review tab closes it (same as the close button).
- Avatar robustness: the placeholder is drawn while a picture downloads or decodes and whenever it fails (download error, non-image reply, corrupt file); downloads are only cached if they start with a PNG/JPEG/GIF/WebP signature.
- My reviews redesign (GitHub issue-browser style): the role chips are gone. Default lists everything reviewable: GitHub = pulls of the 40 most recently pushed non-archived repos with push permission (30 each), GitLab = MRs of the 40 most recently active projects with min_access_level 30 (30 each); queried concurrently, a failing repo/project is skipped. Author/Assignee/Label are multi-select dropdowns (`app::mine`, tested): OR inside a filter, AND between filters, "Me" resolves per host, and each dropdown lists only values present on the items passing every other filter (selected values stay listed so they can be removed). The reviewer toggle maps to GitLab `reviewer_username`-style data; on GitHub it deliberately stays the same as the default, as requested (GitHub does return `requested_reviewers` per pull, so it could be narrowed later). Hide-drafts chip dropped (`-is:draft` still works in the search box).
- Home starts on the tab chosen in Settings (Recent by default); with an empty Recent reviews list it always starts on My reviews. Applied at startup only, so the list never jumps under the user.
- Remembered state: the My reviews filters (remote, state, reviewer toggle, author/assignee/label choices, search text) are global in `~/.config/perusal/ui_state.toml`, written whenever they change; a review's file filter expression and sort are stored per review in the database (`review_ui`) and win over the preset default when it is reopened, even if cleared.
- Leaving a review: closing a tab (button, middle click, Ctrl+W) or the window asks Submit/Finish, Keep for later, Discard or Cancel when the review is unfinished, meaning not submitted and it has drafts or is partly viewed (0 viewed and no drafts, or all viewed with no drafts, close silently). New drafts or viewed marks after a submit make it unfinished again. Quitting asks about each unfinished tab in turn. Submit opens the Finish dialog on that review rather than posting blindly (verdict and summary are needed).
- Tabs can be dragged to reorder (drop on the tab whose position you want). Ctrl+F finds in the diff (matched words highlighted, other rows such as comments tinted) and on the overview (matched words highlighted in the title, rendered description and comments, including inside bold, links, lists, tables and code; matches are counted per text run and the view scrolls to the section holding the current one; a match cannot span two runs, for example across a paragraph break); ASCII case-insensitive, Enter/Shift+Enter or F3 step, Esc closes.
- The comment composer has a Publish now button on remote reviews (hidden when 'publish comments instantly' is on, where Add draft already posts): the comment is saved as a draft first, then posted, so a failed post keeps it as a draft.
- Grouped rendered Markdown: each block of each file is its own selectable row (same selection, toolbar and comment cards as code lines), so blocks can be commented on while a group is shown rendered. A comment on any line of a block appears under that block.
- Review panel: a divider between Commits and Drafts can be dragged to resize them (Commits keeps its natural height up to 260 px until first dragged, then the chosen height is saved as `commits_height`; Drafts takes the rest).
- Every error message section has a copy button (toasts of kind error, My reviews host errors, Home open errors, filter/sort and AI-generation errors, AI run errors, finish/submit errors, settings messages, account token problems, grouping rule errors); it copies the full text.
- Avatar downloads: a token header is only sent to the exact host (and port) of the avatar URL and redirects with a token are followed only within it; the body is streamed and aborted past 2 MB. A listing where every repository or project failed is returned as an error instead of an empty list.
