# Decisions
- Name `perusal`, isolated in `crates/core/src/brand.rs` (spec).
- License MIT OR Apache-2.0; LICENSE-APACHE holds a pointer to the canonical text rather than the full text (fetch full text before release).
- GPUI not wired in M0: app crate is a stub so `cargo build --workspace` stays fast and green; the GPUI pin is chosen when M3 starts, per spec.
- Synthetic MR generator lives in `perusal-cli` (`perusal-cli gen <dir>`), using the git CLI.
- Line/word diff uses `similar` (inline feature) instead of imara-diff: stable API, built-in word-level inline changes.
- Tree-sitter highlighting ships rust and python grammars first; other languages load lazily in later work (return no spans now).
- Re-anchor of drafts across a head move uses a line-diff map; ranges where either end changed are flagged for manual placement.
- Token storage: FileStore (mode 0600, outside SQLite) is implemented; OS keychain backend (keyring crate needs libdbus) is deferred behind a future `keychain` feature. File is not encrypted; documented risk.
- GitLab viewed-state: the API exposes none, so marks stay local (`Unsupported`). GitLab "request changes" has no equivalent: submit returns `Unsupported` and the UI hides the control.
- GitHub viewed sync uses GraphQL markFileAsViewed/unmarkFileAsViewed (needs PR node id lookup first); implemented but only mock-tested.
- GitLab submit sends positions with null base/start SHA; real instances need the MR diff_refs filled in (to verify against a live host).
- GPUI (superseded by the next entry): crates.io `gpui` 0.2.2 was fetched but fails to compile in this sandbox (transitive `xattr` cannot find libc::ENOATTR on this toolchain/libc, also after `cargo update`). No window could be built or run, so `perusal-app` is a lib of tested view models (vm, tabs, keymap, theme) plus a stub binary. Wiring GPUI (pinned) is the first step on a machine where it builds; the view-model API is what the views bind to.
- Built-in theme colors are first-pass values validated by `perusal theme check` contrast rules, not hand-tuned.
- GPUI resolved: Zed's git GPUI pinned to rev 0855410ccd2040efbbf14d71409166b6c472e0bd (2026-09-01) builds and runs (latest Zed head needs an unstable rustc feature, `trim_prefix_suffix`, and crates.io 0.2.2 trips on `xattr`). Linux needs libxkbcommon-dev, libxkbcommon-x11-dev and libwayland-dev at link time. The GUI lives in `crates/ui` (bin `perusal`), a workspace member but not a default member, so `cargo build` stays light; build it with `-p perusal-ui`. `gpui_platform` is used with font-kit, wayland, x11.
- GUI v0 scope: local-branch review window (file list, virtualized diff with tree-sitter colours and word highlights, progress bar, filter bar, batch flow, commit graph with click-to-scope, draft comments, zoom). Not yet: tabs, side-by-side view, recent-reviews page, quit prompt, command palette, remote MR opening, submit dialog, thread display, AI chat, CI icon, theme/keymap file loading (keys are hard-coded).
